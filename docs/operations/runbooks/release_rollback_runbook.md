# Runbook: تراجع إصدار النواة المدمجة

- **المعرّف:** RB-OPS-002 / `P7-03`
- **الجمهور:** مالك الإصدار + التطبيق المضيف + مسؤول قاعدة البيانات
- **النطاق:** تراجع مكتبة `pkg/sdk` المدمجة ومخطط PostgreSQL؛ لا يوجد خادم HTTP/gRPC أو بوابة شبكية داخل النواة.
- **المرجع:** [تقرير التحقق النهائي](../../reports/KERNEL_FINAL_VERIFICATION_REPORT.md) *(سجل تاريخي)*، [اعتماد الإصدار](../../reports/KERNEL_RELEASE_SIGNOFF.md) **`SUPERSEDED` — لا يعتمد كإذن نشر حالياً**؛ راجع [تحليل التضاربات](../../analysis/DOCS_CONFLICT_ANALYSIS.md).

## 1. متى يُفعّل التراجع

- فشل أي بوابة قبول تشغيلية `G1`–`G6` بعد تشغيل `P7-04`، أو أي بوابة جودة رسمية `G01`–`G11` ([المواصفة](../../quality/QUALITY_GATES_SPECIFICATION.md)، [الخريطة](../../quality/QUALITY_GATES_CROSSWALK.md))، أو ظهور خلل محاسبي في الإنتاج (عدم توازن، حفظ جزئي، تسريب بين الشركات، انقطاع سلسلة التدقيق).
- انخفاض الأداء تحت حمل 1000 TPS عن `P50 ≤ 15 ms` أو `P95 ≤ 50 ms` بعد نشر جديد. هذه العتبات أهداف تشغيلية محلية؛ العيّنة المسجّلة في [performance_samples.json](../../reports/performance_samples.json) تُظهر `p50 ≈ 238.7ms` و`p95 ≈ 337.7ms` عند ~63 TPS، وهدف 1000 TPS ما زال غير معتمد بيئياً ([معايير النجاح](../../rules/ACCOUNTING_ENGINE_SUCCESS_CRITERIA.md)). لا تُترجم أرقام `ms/op` في تقارير الـ benchmark إلى أرقام حمل.
- تعذّر تفسير سجل `schema_migrations` أو فشل `ValidateSchema` في الإصدار الجديد.

## 2. الاحتواء الفوري (قبل أي تعديل)

1. أوقف توسيع النشر الجديد ووجّه التطبيق المضيف إلى الإصدار السابق المعتمد إن أمكن دون تغيير المخطط.
2. احتفظ بنسخة `pg_dump --format=custom` من الحالة الحالية قبل أي تراجع أو إصلاح.
3. سجّل: الإصدار الجديد، الإصدار المرجعي للتراجع، وقت الفشل، البوابة الفاشلة، وأثر البيانات (قيود جديدة، هجرات مطبقة).
4. لا تحذف أو تعدل صفوف `schema_migrations` يدوياً، ولا تشغّل إصداراً أقدم على مخطط أحدث.

## 3. مسارات التراجع

### أ) تراجع الكود فقط (بدون تغيير مخطط)

إذا كان الإصدار الجديد لم يطبّق هجرات قاعدة بيانات:

```bash
# في التطبيق المضيف: العودة إلى artifact الإصدار السابق المعتمد، ثم إعادة البناء
git checkout <previous-approved-tag>
go build ./...
./scripts/verify_architecture.sh
./scripts/check_api_compat.sh
go test -race ./...
```

أعد تشغيل `T0`–`T7` كما هي قبل إعلان العودة. لقطة `docs/api/v1.snapshot` لا تُرَجَّع إلا بقرار Major موثّق.

### ب) تراجع مع تغيير مخطط

1. قيّم أثر `.down.sql` على البيانات الجديدة؛ التراجع ليس آمناً تلقائياً لأنه قد يحذف قيوداً أو يتعارض مع كتابات الإصدار الجديد.
2. جرّب التراجع أولاً على نسخة مستعادة من النسخة الاحتياطية في بيئة معزولة (`POSTGRES_URL` مستقل).
3. إذا كانت هناك بيانات تعتمد على المخطط الجديد، فضّل **roll-forward** بهجرة تصحيحية على التراجع، أو استعد من نقطة معتمدة وفق [Runbook الاستعادة](disaster_recovery_runbook.md).
4. بعد أي تراجع مخطط، تحقق من `ValidateSchema`، توازن القيود، مطابقة الأرصدة، وسلامة سلسلة التدقيق قبل فتح الكتابة.

### ج) تراجع بوابة التوافق (API)

إذا كشف `check_api_compat.sh` تغييراً غير معلن في توقيع عام: أوقف النشر، العودة إلى الكود السابق، ثم حدّث اللقطة صراحةً عبر `./scripts/check_api_compat.sh --update` فقط عند كسر مقصود وموثّق بـ SemVer Major، وأعد `T0`/`T1`.

## 4. التحقق والإغلاق

| الفحص | الأمر | الشرط |
| :--- | :--- | :--- |
| العزل المعماري | `./scripts/verify_architecture.sh` | PASS |
| توافق API | `./scripts/check_api_compat.sh` | exit 0 |
| السباقات | `go test -race ./...` | 0 Data Races |
| الذرية والتكافؤ | اختبارات التكافؤ في [مجموعة اختبارات العقد](../../contracts/KERNEL_CONTRACT_TEST_SUITE.md) | 0 Partial Writes |
| التغطية | `scripts/check_coverage.sh coverage.out` | ≥ 80% **للمستودع كاملاً**؛ هذه ليست بوابة النواة: تغطية `internal/kernal/...` المستهدفة > 95% ([معايير النجاح](../../rules/ACCOUNTING_ENGINE_SUCCESS_CRITERIA.md))، و`coverage.out` الكامل سجّل 52.5% في [سجل الاستثناءات](../../../internal/kernal/KERNEL_COVERAGE_EXCEPTIONS.md). لا تُستخدم تغطية وحدها كشرط GO. |
| الاستعادة | `go test -v ./test/dr` | PASS |

لا يُغلق الحادث حتى تتوفر وثيقة اعتماد إصدار **سارية** بحالة `GO` للإصدار المرجعي بتوقيع جهة معتمدة معلومة. [اعتماد الإصدار الحالي](../../reports/KERNEL_RELEASE_SIGNOFF.md) مُلغى (`SUPERSEDED`) ولا يكفي لإغلاق الحادث؛ بدلاً منه يُسجَّل في سجل الحادث قرار `NO-GO`/مؤجل مع موانعه حتى صدور اعتماد جديد يغطي بوابات `G01–G11`. أرفق الإصدار، الهجرة، القرار، الأثر، ونتائج التحقق في سجل الحادث، وأضف اختبار انحدار يمنع تكرار السبب.
