## 3. قواعد مقترحة (صياغة جاهزة للإضافة)

1. **تعريف القرارات والسلطة:** «لكل بوابة أحد ثلاثة قرارات: `PASS` = استيفاء كل معايير المرحلة دون فجوة Critical أو High مفتوحة داخل نطاقها ودون دليل قديم؛ `CONDITIONAL` = مخالفة مؤجلة مصنّفة بمالك ومرحلة إغلاق وتاريخ، ولا تُعدّ إذناً للإصدار ولا لبدء مرحلة تعتمد على العمل المؤجل؛ `FAIL` = فجوة Critical، أو اختبار فاشل، أو دليل غير قابل لإعادة الإنتاج. يُعيَّن مالك قرار لكل بوابة في خط الأساس ويُسجَّل اسمه وتاريخه ولا يجوز أن يكون المنفذ وحده مراجعاً.»
2. **مسار الفشل:** «عند فشل مهمة تُوقف فوراً، يُسجَّل دليل الفشل وتصنيفه ومالكه، وتُعاد دورة RED→GREEN، ثم تُعاد بوابة المرحلة كاملة. لا يُعتبر الفشل بيئياً إلا بدليل بيئي مستقل وتوقيع مالك البوابة.»
3. **المراجعة المستقلة:** «لا تُغلق بوابة ولا يُصنَّف تغيير حرج `PASS` قبل إدراج اسم مراجع مستقل مختلف عن المنفذ، وتاريخ المراجعة، وقائمة تحقق، ونتيجة صريحة. أي عبارة «بانتظار المراجعة» تعني `CONDITIONAL`.»
4. **الأدلة:** «كل نتيجة تُعتمد في بوابة تُحفظ داخل المستودع أو ببصمة محتوى ومسار دائم، مع الأمر وإصدار Go والبيئة ورمز الخروج الفعلي. لا تُقبل سطور السجل المجمّلة بديلاً عن رمز الخروج، وتُصلح أي أداة لا تُمرّره قبل استخدامها كدليل.»
5. **تغطية المهام:** «يحتوي تقرير كل مرحلة على جدول يطابق مهام الخطة بأرقامها الأصلية (`P3-4`، `P9-13`…) مع إحدى الحالات `PASS` أو `PARTIAL` (فجوة + مالك + مرحلة) أو `N/A` (سبب موثق). لا يُقبل جدول مُعاد ترقيمه كدليل على اكتمال 15/15.»
6. **العمل المؤجل:** «أي مهمة غير مكتملة لا تُحسب `PASS`؛ تُسجَّل فجوة بمالك ومرحلة إغلاق قبل إعلان البوابة، ويُوسَم الحكم بـ `PASS-SCOPED` مع بيان النطاق، ولا يُستخدم لفتح مرحلة تعتمد على العمل المؤجل.»
7. **تثبيت اللقطة (Snapshot Pinning):** «كل قرار تحقق يعتمد على Master Data أو فترة أو سياسة أو سعر يُثبَّت في لقطة مجمدة تحمل `CompanyID` والزمن والمصدر، وتُمرَّر إلى Executor مع الطلب. يُمنع إعادة قراءة الكيان بعد التحقق لغرض الأهلية أو الفترة أو السياسة، وعلى Adapter رفض طلب تختلف لقطته عن اللقطة المختومة أو انتهت نافذتها.»
8. **تصنيف الأخطاء:** «يُسجَّل كل خطأ تعارض أو تكرار أو قفل أو نتيجة غير معروفة في كتالوج موحد قابل للتنقل بين النواة و`pkg/spi` وSDK مع `retryable/non-retryable`. لا يُعد خطأ جديد مكتملاً بدونه، ولا يُصنَّف بالافتراض.»
9. **النسخ الدفاعي:** «كل دالة مُصدَّرة تُرجع slice أو map أو pointer أو بنية متداخلة من حالة داخلية تُرجع نسخة دفاعياً؛ ويُثبت باختبار أن تعديل القيمة المُرجَعة لا يغيّر الحالة الأصلية.»
10. **Fuzz وMutation:** «تُثبَّت مدة Fuzz لكل مرحلة في خط الأساس ولا تُغيَّر إلا بقرار موثق. أي مدخل `interesting` يُقلَّل ويُحفظ في `testdata/fuzz` في نفس المرحلة أو يُسجَّل كفجوة بمالك. Mutation Testing إما بأداة مُثبَّتة تُعاد نتائجها، أو باستثناء رسمي يحدد البديل وحدوده؛ ولا يُعلن `PASS` على نسبة غير معاد إنتاجها.»
11. **قائمة Adapters:** «تُثبَّت قائمة «Adapters المستهدفة» في المرحلة 0 (حالياً: Memory وPostgreSQL) ولا تتغير إلا بـ ADR؛ كل عبارة «جميع Adapters» تُحال إلى هذه القائمة.»
12. **قالب التقرير:** «كل تقرير مرحلة يلتزم بالقالب: رمز الوثيقة، المرجع/الالتزام وإصدار Go، النطاق، جدول المهام بأرقام الخطة، التغييرات وسببها، أوامر التحقق ورموز الخروج، جدول `G1–G15` مع `PASS/FAIL/N/A` وسبب `N/A`، الفجوات، المراجع المستقل، المخاطر المتبقية، وتاريخ/قرار البوابة.»
