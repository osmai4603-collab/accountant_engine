# المرحلة P7: التحصين والجودة والاعتماد النهائي (Hardening & Release)

- **الهدف المحوري للمرحلة:** إخضاع النواة المحاسبية المعاد بناؤها لفحوصات الجودة والأمان والأداء الصارمة (تحليل الاعتماديات الساكن، اختبارات التزامن والسباق Race Detection، اختبارات الذرية وحقن الأعطال، واختبارات قياس الأداء للوصول إلى $P95 \le 50\,\text{ms}$)، وتثبيت خط أساس التوافق العكسي (API Snapshot) وإصدار النسخة الأولى المعتمدة للنواة.
- **الاعتماديات العامة للمرحلة:** اعتماد المرحلة `P6`.
- **بوابة اعتماد المرحلة:** إغلاق كافة بوابات القبول الست (G1 إلى G6) بنتيجة GO، وتحقيق تغطية اختبارية $\ge 80\%$، وتحقيق زمن استجابة ترحيل $P95 \le 50\,\text{ms}$.

---

## تفاصيل مهام المرحلة P7

### `P7-01` — تشغيل فحوصات الاستقلالية المعمارية وخلو النواة من البروتوكولات والمصادقة

- **المشكلة التي تحلها:**  
  قبل اعتماد الإصدار، يجب إثبات أن النواة المحاسبية لم تتلوث بأي مكتبة نقل شبكي أو مصادقة، وأن شجرة التبعيات تتوافق بنسبة 100% مع الميثاق المعماري دون أي ثغرة استيراد خفية.

- **الهدف الذي تحققه:**  
  تنفيذ فحص معماري شامل ومؤتمت يثبت رياضياً وبرمجياً:
  1. خلو كافة حزم `internal/*` من استيراد `net/http` أو `google.golang.org/grpc`.
  2. خلو السطح العام `pkg/api` و `pkg/spi` من استيراد أي حزمة داخلية.
  3. خلو النواة `internal/kernal` من استيراد أي حزمة مدارية أو حزمة تخزين.
  4. انعدام التبعيات الدائرية.

- **نطاق المهمة:**  
  - يشمل: تشغيل `scripts/verify_architecture.sh`، فحص `go list -f`، وتحليل `go mod graph`.

- **خطوات التنفيذ التفصيلية:**
  - **ما يجب بناؤه من جديد (Build New):**
    - توليد تقرير فحص معماري رسمي موثق وموقع يثبت نقاء النواة بنسبة 100%.
  - **ما يجب فحصه وتعديله (Verify & Modify):**
    - معالجة أي استيراد شارد يظهر في مخرجات التحليل وإعادة توجيهه للموانئ المجردة.

- **الاعتماديات:** اعتماد المرحلة `P6`.

- **معايير القبول:**
  - [ ] نتيجة فحص `verify_architecture.sh` خضراء 100% دون أي استثناء.
  - [ ] انعدام تام لأي مرجع لحزم gRPC أو HTTP داخل النواة.

### `P7-02` — تشغيل حزمة اختبارات الذرية (ACID)، كشف السباق (Race)، وقياس الأداء (Benchmarks)

- **المشكلة التي تحلها:**  
  لا يمكن الجزم بموثوقية المحرك المحاسبي في بيئات الإنتاج الحقيقية دون إخضاعه لحمل مالي متزامن مكثف، واختبارات كشف السباق التزامني (Race Conditions)، واختبارات حقن الأعطال لإثبات الذرية التامة (All-or-Nothing).

- **الهدف الذي تحققه:**  
  1. تشغيل اختبارات السباق المالي: `go test -race ./...`.
  2. تشغيل اختبارات حقن الأعطال: إثبات التراجع التام عند انقطاع الاتصال أو فشل قاعدة البيانات أثناء ترحيل قيد.
  3. تشغيل حزمة قياس الأداء `test/benchmark/`: إثبات تحقيق زمن ترحيل القيد $P95 \le 50\,\text{ms}$ و $P50 \le 15\,\text{ms}$ تحت حمل 1,000 TPS.

- **نطاق المهمة:**  
  - يشمل: `test/atomic/`, `test/acid/`, `test/benchmark/`.

- **خطوات التنفيذ التفصيلية:**
  - **ما يجب نسخه وتعديله (Copy & Modify):**
    - نسخ اختبارات الذرية والتزامن من `accounting_engine/test/atomic/` و `test/concurrency/`.
    - نسخ بروتوكول القياس من `accounting_engine/test/benchmark/benchmarks_test.go` وتكييفه.
  - **ما يجب بناؤه من جديد (Build New):**
    - توليد تقرير قياس الأداء الرسمي `docs/performance_baseline_report.md` مسجلاً فيه نتائج P50, P95, P99 واستهلاك الذاكرة ومواصفات البيئة.

- **الاعتماديات:** `P7-01`.

- **معايير القبول:**
  - [ ] اجتياز اختبار `go test -race ./...` بنجاح دون تسجيل أي سباق بيانات (Zero Data Races).
  - [ ] تسجيل صفر حالات لحفظ جزئي (Zero Partial Writes) في اختبارات حقن الأعطال.
  - [ ] زمن ترحيل القيد $P95 \le 50\,\text{ms}$ وفق تقرير الأداء المعتمد.

### `P7-03` — تثبيت لقطة العقد العام (API Snapshot) والاعتماد النهائي للإصدار

- **المشكلة التي تحلها:**  
  بعد إنجاز المحرك، يجب تثبيت خط أساس للواجهات البرمجية (API Contract Baseline) لمنع حدوث أي كسر غير مقصود في التوافق العكسي مستقبلاً عند تحديث المحرك.

- **الهدف الذي تحققه:**  
  توليد لقطة العقد البرمجي المعتمد `docs/api/v1.snapshot`، تشغيل بوابة توافق الواجهات `scripts/check_api_compat.sh` بنجاح، وتوقيع تقرير إغلاق المرحلة واعتماد الإصدار الأول للنواة المستقلة (`v1.0.0-kernal`).

- **نطاق المهمة:**  
  - يشمل: `docs/api/v1.snapshot`, تقرير الجاهزية النهائية للإصدار.

- **خطوات التنفيذ التفصيلية:**
  - **ما يجب بناؤه من جديد (Build New):**
    - توليد لقطة الواجهات البرمجية العامة لـ `pkg/sdk`, `pkg/api/v1`, و `pkg/spi`.
    - إنشاء ملف تقرير إغلاق الخطة واعتماد الإصدار `docs/release_signoff_v1.0.0.md`.
  - **ما يجب نسخه وتعديله (Copy & Modify):**
    - تكييف سكربت `scripts/check_api_compat.sh` ليعمل ضد اللقطة الجديدة.

- **الاعتماديات:** `P7-01`, `P7-02`.

- **معايير القبول:**
  - [ ] ملف `docs/api/v1.snapshot` موجود ومحدث ومطابق للعقود العامة.
  - [ ] سكربت فحص توافق الـ API يمر بنجاح بنسبة 100%.
  - [ ] استيفاء كافة معايير القبول والنجاح وتوقيع تقرير الجاهزية للإنتاج.
