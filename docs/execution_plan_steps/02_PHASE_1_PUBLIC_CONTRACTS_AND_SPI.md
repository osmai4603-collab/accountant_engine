# المرحلة P1: العقود العامة وموانئ SPI (Public Contracts & SPI)

- **الهدف المحوري للمرحلة:** بناء ونقل العقود العامة المجردة ونماذج البيانات غير القابلة للتغيير (`pkg/api/v1/*`)، وتأسيس موانئ مزودي التخزين والخدمة (`pkg/spi/*`) كعقود خالصة مستقلة عن أي تفاصيل لقاعدة البيانات أو بروتوكولات النقل، لتمكين النواة من الاعتماد عليها وفق مبدأ عكس التبعية (DIP).
- **الاعتماديات العامة للمرحلة:** اعتماد المرحلة `P0`.
- **بوابة اعتماد المرحلة:** نجاح بناء حزم `pkg/api/v1/...` و `pkg/spi/...` بدون أخطاء، واجتياز فحص النقاء المعماري (عدم استيراد أي حزمة داخلية أو حزمة قاعدة بيانات داخل العقود العامة).

---

## تفاصيل مهام المرحلة P1

### `P1-01` — نقل وتدقيق العقود والنماذج المعيارية العامة (`pkg/api/v1/*`)

- **المشكلة التي تحلها:**  
  الأنظمة المضيفة تحتاج إلى التخاطب مع المحرك المحاسبي بنماذج بيانات واضحة ومستقرة ومعيارية (مثل `JournalEntry`, `AccountingEvent`, `TrialBalance`, `Account`) دون الارتباط بالهياكل التخزينية الداخلية أو حزم قاعدة البيانات.

- **الهدف الذي تحققه:**  
  توفير نماذج بيانات ثابتة، مجردة، ومحمية من التعديل العشوائي داخل `pkg/api/v1/` تغطي كافة مجالات التخاطب المالي (القيود، الأحداث، التقارير، الدفاتر الفرعية، والمعرفات العامة).

- **نطاق المهمة:**  
  - يشمل:
    - `pkg/api/v1/types/`: المعرفات الأساسية (`CompanyID`, `AccountID`, `JournalEntryID`, `Money`, `Currency`).
    - `pkg/api/v1/ledger/`: نماذج القيد العام (`JournalEntry`, `JournalEntryLine`, `PostingStatus`, `Account`, `Period`).
    - `pkg/api/v1/events/`: نموذج الحدث الاقتصادي المعياري (`AccountingEvent`, `EventAccountMapping`).
    - `pkg/api/v1/reporting/`: كائنات ميزان المراجعة والمركز المالي وقائمة الدخل والتدفقات النقدية.
    - `pkg/api/v1/subledger/`: كائنات أطراف التعامل للدفاتر المساعدة (AR, AP, Cash, Assets).
  - لا يشمل: منطق الترحيل أو حفظ البيانات.

- **خطوات التنفيذ التفصيلية:**
  - **ما يجب نسخه (Copy):**
    - نسخ ملفات `pkg/api/v1/types/*.go` من المشروع المرجعي `accounting_engine` (مع التحقق من استقلاليتها).
    - نسخ نماذج `pkg/api/v1/ledger/*.go` (نماذج القيود والحسابات والفترات).
    - نسخ نماذج `pkg/api/v1/events/*.go` (نماذج الأحداث الاقتصادية).
    - نسخ نماذج `pkg/api/v1/reporting/*.go` و `pkg/api/v1/subledger/*.go`.
  - **ما يجب تعديله (Modify):**
    - تدقيق استيرادات الحزم والتأكد من أنها تستورد فقط الحزم القياسية أو حزمة `shopspring/decimal` أو `google/uuid`.
    - حذف أي أوسمة (Struct Tags) خاصة بـ Protobuf أو gRPC serialization من النماذج إن وجدت؛ فالنماذج عامة لمكتبة Go.
    - التأكد من إزالة أي دوال تعتمد على دوال التخزين الداخلية.
  - **ما يجب بناؤه من جديد (Build New):**
    - توثيق تعليقات Go Doc واضحة على كل كائن تحدد طبيعته كـ Immutable Value Object.

- **الاعتماديات:** اعتماد المرحلة `P0`.

- **معايير القبول:**
  - [x] حزمة `pkg/api/v1/...` تُبنى بنجاح عبر `go build ./pkg/api/v1/...`.
  - [x] لا تحتوي أي ملف في `pkg/api/v1` على `import` يشير إلى `internal` أو `grpc` أو `database/sql`.
  - [x] كافة أنواع المبالغ في النماذج تستخدم `Money` أو `decimal.Decimal` مع حظر تام لـ `float32/64`.

### `P1-02` — نقل وتجريد موانئ مزودي التخزين والخدمة (`pkg/spi/storage` و `pkg/spi/standards`)

- **المشكلة التي تحلها:**  
  في المشروع القديم، كانت بعض عقود التخزين مختلطة بـ `pkg/spi/legacy` التي تفرض واجهة `CoreLedgerStore` المتضخمة وتعيق العزل النقي للنواة. نحتاج إلى موانئ تخزين دقيقة وذرية وفق مبدأ فصل الواجهات (ISP).

- **الهدف الذي تحققه:**  
  توفير واجهات مجردة بالكامل (Interfaces) تُمثل عقود التخزين (`storage.Ports`, `storage.UnitOfWork`, `storage.EntryStore`, `storage.AccountStore`, `storage.BalanceStore`, `storage.AuditStore`) وعقود المعايير (`standards.StandardModule`)، بحيث تتحدث النواة مع هذه الموانئ دون أن تدري ما إذا كان المحول يعمل في الذاكرة أو على PostgreSQL.

- **نطاق المهمة:**  
  - يشمل: `pkg/spi/storage/`, `pkg/spi/masterdata/`, و `pkg/spi/standards/`.
  - يستبعد صراحة: حزمة `pkg/spi/legacy/`؛ حيث يتم شطبها نهائياً.

- **خطوات التنفيذ التفصيلية:**
  - **ما يجب نسخه (Copy):**
    - نسخ واجهات التخزين الحديثة من `accounting_engine/pkg/spi/storage/`:
      - `ports.go`: تعريف هيكل `Ports` الذي يجمع موانئ التخزين المجردة.
      - `transaction.go`: تعريف عقد وحدة العمل الذرية `UnitOfWork` و `TransactionContext`.
      - `entries.go`, `accounts.go`, `balances.go`, `audit.go`, `events.go`.
    - نسخ عقود الموديلات المعيارية من `accounting_engine/pkg/spi/standards/module.go`.
    - نسخ عقود البيانات الرئيسية من `accounting_engine/pkg/spi/masterdata/`.
  - **ما يجب تعديله أو استبعاده (Modify/Exclude):**
    - استبعاد وحذف مجلد `pkg/spi/legacy/` بالكامل؛ لا وجود لـ `CoreLedgerStore` بعد اليوم.
    - تنظيف توقيعات الدوال لتعتمد حصراً على كائنات `pkg/api/v1/*` وسياق `context.Context`.
  - **ما يجب بناؤه من جديد (Build New):**
    - دالة تحقق هيكلي `Ports.Validate()` تضمن عدم تمرير منفذ تخزين فارغ (nil) قبل بدء المحرك.

- **الاعتماديات:** `P1-01`.

- **معايير القبول:**
  - [x] حزمة `pkg/spi/storage` تُبنى بنجاح وتُصدر واجهات التخزين المستقلة.
  - [x] غياب تام لأي حزمة أو مرجع لـ `legacy`.
  - [x] لا تحتوي واجهات SPI على أي نوع أو استيراد من حزم `internal` أو حزم SQL.

- **ملاحظة التوازي:** يمكن تنفيذ هذه المهمة بالتوازي مع `P1-03` نظراً لعدم وجود تداخل في مسارات الملفات.

### `P1-03` — تأسيس عقود سياق الأمان الموثوق المجرد (`pkg/spi/application`)

- **المشكلة التي تحلها:**  
  المحرك القديم كان يتضمن حزمة مصادقة داخلية (`internal/serviceauth`) تفحص توكنات JWT وتتعامل مع تفاصيل التشفير والمفاتيح، مما يكسر مبدأ حيادية الأمان وحظر IAM في النواة. نحتاج إلى واجهة مجردة تقبل سياق الفاعل والشركة الموثوق دون إقحام النواة في التحقق من كلمات المرور.

- **الهدف الذي تحققه:**  
  توفير عقد مجرد لسياق الأمان (`Security Context`) يسمح للنظام المضيف بتمرير هوية المستخدم المصادق عليه (`Principal`) ومعرف الشركة الموثوق (`Company Scope`) عبر `context.Context` وتثبيتها في سجلات التدقيق والعزل، دون امتلاك النواة لأي منطق مصادقة.

- **نطاق المهمة:**  
  - يشمل: `pkg/spi/application/context.go`, `pkg/spi/application/principal.go`.
  - لا يشمل: جداول مستخدمين أو مكتبات JWT.

- **خطوات التنفيذ التفصيلية:**
  - **ما يجب نسخه (Copy):**
    - نسخ تعريفات `Principal` و `CompanyContext` من `accounting_engine/pkg/spi/application/`.
  - **ما يجب تعديله (Modify):**
    - تنظيف الكائنات من أي دوال ترتبط بـ HTTP Headers أو gRPC Metadata؛ التعامل يتم حصراً عبر `context.Context` القياسي في Go.
  - **ما يجب بناؤه من جديد (Build New):**
    - دوال مساعدة لحقن واستخراج السياق المالي بأمان:
      - `WithPrincipal(ctx context.Context, p Principal) context.Context`
      - `PrincipalFromContext(ctx context.Context) (Principal, bool)`
      - `WithCompanyContext(ctx context.Context, c types.CompanyID) context.Context`

- **الاعتماديات:** `P1-01`.

- **معايير القبول:**
  - [x] حقن واسترجاع سياق `Principal` و `CompanyID` يعمل بدقة عبر اختبار وحدة مصاحب.
  - [x] لا يوجد أي استيراد لمكتبات تشفير أو JWT أو شبكات داخل الحزمة.

- **ملاحظة التوازي:** تنفذ بالتوازي مع `P1-02`.
