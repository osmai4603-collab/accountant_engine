# مواصفة بوابات الجودة (Quality Gates Specification)

**المرجع الحاكم:** [معيار جودة النواة المحاسبية](ACCOUNTING_KERNEL_QUALITY_STANDARD.md) — الإصدار 2.0.0.

**الغرض:** تفصيل شروط Pass / Fail / Not Verified / N/A / Waived للبوابات G01–G11. عند التعارض، لا تعدل هذه الوثيقة المعيار الأساسي؛ يُرفع Change Request ويُحدّث الإصداران معاً.

# 8. بوابات الجودة الإلزامية (Quality Gates)

قد يحصل المشروع على 9/10 في المعدل الحسابي، لكنه لا يستحق هذا التصنيف
إذا كان يسمح بترحيل قيد غير متوازن.

لذلك توجد شروط إلزامية لا يمكن تجاوزها.

## البوابات الإلزامية

لكل بوابة Applicability ومتطلبات وأدلة قبول وشروط Pass / Fail / Not Verified / N/A / Waived. لا تستخدم نسبة تغطية الكود وحدها شرطاً للاجتياز.

| Gate | المجال | شروط Pass القابلة للتحقق | الحد الأدنى للدليل |
| --- | --- | --- | --- |
| G01 Accounting Integrity | الثوابت المحاسبية | اجتياز 100% من اختبارات الثوابت الحرجة المنطبقة ACC-001–ACC-013؛ صفر إخفاقات حرجة مفتوحة؛ لا يوجد قيد غير متوازن قابل للترحيل | E3 لكل ثابت حرج |
| G02 Domain Integrity | سلامة المجال | صفر مسارات مدعومة تتجاوز Aggregate Root أو تنشئ حالة مجال غير صالحة؛ 100% من invariants المجال الحرجة لها اختبارات | E3 |
| G03 Transaction Integrity | الذرية والتزامن والتكرار | نجاح جميع اختبارات Commit/Rollback والفشل المحقون والتزامن وIdempotency؛ صفر آثار جزئية أو مكررة تخالف العقد في مجموعة الاختبارات | E3، وE4 إذا كان الادعاء بيئياً |
| G04 Monetary Integrity | المال والعملات | 100% من سيناريوهات التحويل والتقريب والتوزيع الحرجة ناجحة؛ صفر فروقات غير مفسرة؛ توازن وظيفي عند انطباق ACC-013 | E3 |
| G05 Lifecycle & Period Integrity | دورة الحياة والفترات | رفض 100% من الانتقالات غير المسموحة في الاختبارات المحددة؛ لا تعديل مباشر للتاريخ المرحل؛ نجاح سيناريوهات الإغلاق وإعادة الفتح المنطبقة | E3 |
| G06 Historical & Audit Integrity | التدقيق والتاريخ والمصدر | كل فئة عملية تتطلب تتبعاً لها Audit Event ومصدر أو سبب بديل؛ نجاح اختبارات كشف التعديل غير المصرح وفقدان الأثر | E3 |
| G07 Persistence Integrity | عقود التخزين | اجتياز 100% من Persistence Contract Tests لكل Adapter معلن دعمه، بما فيها rollback وuniqueness وconcurrency وmigration حيث تنطبق؛ صفر اختلافات غير مفسرة | E3، وE4 عند ادعاء خصائص هدف |
| G08 Isolation Integrity | عزل Tenant وLedger | نجاح جميع اختبارات العزل الإيجابية والسلبية؛ صفر حالات تسرب أو وصول عابر للنطاق في الاختبارات | E3 |
| G09 Architectural Integrity | حدود المعمارية | صفر مخالفات غير معتمدة لقواعد اتجاه الاعتماد وحدود النواة؛ كل استثناء موثق ومقبول مسبقاً | E2/E3 حسب الادعاء |
| G10 Verification Integrity | التحقق والأدلة | 100% من مجموعات الاختبارات الحرجة المطلوبة منفذة وناجحة؛ لكل ثابت حرج اختبار مرجعي ودليل E3؛ صفر متطلب حرج Not Verified | E3 |
| G11 Operational Integrity | التشغيل والاستعادة | اجتياز اختبارات الاستعادة والترحيل والتوافق؛ تحقيق SLO/RPO/RTO المعلنة في Target Environment أو بيئة مكافئة؛ لا فقد بيانات خارج الحدود المعلنة | E4 للادعاءات التشغيلية البيئية |

تفسير الحدود:

- تعني نسبة 100% جميع حالات الاختبار المحددة والمعتمدة للمتطلب، لا جميع الحالات الممكنة رياضياً.
- أي اختبار حرج فاشل يمنع Pass حتى إصلاحه أو اعتماده كاستثناء رسمي وفق سياسة Waiver.
- لا تُحسب حالات N/A إلا بموافقة Scope Profile، ولا يجوز تحويل Not Verified إلى N/A.
- E3 يثبت تحققاً آلياً أو قابلاً لإعادة التشغيل في بيئة اختبار موثقة.
- E4 يثبت التحقق في Target Environment أو بيئة ثبت تكافؤها مع توثيق الفروقات وموافقة المراجع المستقل.
- لا يُفرض E4 على كل ثابت مجال إذا كان E3 كافياً لإثباته؛ يحدد الحد الأدنى لكل متطلب.

**حالات البوابة:**

- **Pass:** تحققت جميع شروط الاجتياز المنطبقة.
- **Fail:** ثبت خرق شرط إلزامي أو فشل اختبار حاسم.
- **Not Verified:** لا توجد أدلة كافية للحكم.
- **N/A:** البوابة أو جزء منها غير منطبق بموافقة Scope Profile.
- **Waived:** استثناء رسمي؛ يعرض منفصلاً ولا يُخفى داخل Pass.

### أدلة اجتياز البوابات

لكل Gate يجب تسجيل: المتطلبات، معرفات الثوابت المرتبطة، مسارات الكود،
الاختبارات المنفذة، نتائج التشغيل، البيئة، Commit، الاستثناءات، والقرار.
لا يكفي وجود اسم حزمة أو واجهة أو تعليق برمجي لإثبات الاجتياز.
