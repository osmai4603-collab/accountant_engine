## 1. الغرض والنطاق

يحوّل هذا العقد مسؤولية `RULE-KERNEL-027` من عبارة «الذرية على عاتق المضيف» إلى حدود قابلة للاختبار. يغطي:

- `PostingExecutor` / `PostingReversalExecutor` كما يستدعيهما `PostingPipeline.PostEntry`.
- `storage.PostingWriter.CommitPosting` وما يلزمه من منافذ `storage.IdempotencyStore` و`storage.AuditWriter` وقراءات الأرصدة.
- Adapter الذاكرة وAdapter PostgreSQL من حيث النتيجة المرصودة فقط، لا من حيث التفاصيل البرمجية.

لا يضيف هذا العقد قاعدة محاسبية ثامنة وعشرين، ولا يسمح للنواة بفتح معاملة أو حجز قفل أو معرفة محرك تخزين.

## 2. حدود المسؤولية

| الطرف | ما يملكه | ما لا يملكه |
|---|---|---|
| Kernel `posting` | Clone، التحقق، السياسة، التقريب، التوازن، ختم الحالة والتواريخ، بناء النطاق والبصمات، وتمريرها في `PostOptions` | فتح/إغلاق Transaction، قفل الصفوف، كتابة idempotency، إعادة المحاولة، اختيار SQL أو محرك تخزين |
| SDK / Application | نسخ العقد المختوم إلى `PostingCommit`، فحص آمن بالمفتاح قبل تكرار منطق السياسة، وتصنيف الأخطاء للمستهلك | تعديل النطاق أو البصمة، اعتبار الفشل قبل Commit نجاحاً، تجاهل أخطاء التدقيق |
| Storage Adapter | تنفيذ وحدة العمل كاملة أو إلغاءها، فرض التفرد، جعل أثر التدقيق جزءاً من الالتزام، إرجاع sentinels محايدة، دعم نقاط الحقن في الاختبارات | إعادة تفسير القيد، تغيير المبالغ أو التصنيف أو التاريخ المختوم، إخفاء تعارض الحمولة |

## 3. عناصر وحدة العمل

تنجح كل عناصر وحدة العمل معاً أو لا ينجح شيء منها:

| العنصر | المحتوى الإلزامي | سبب الضم إلى الوحدة |
|---|---|---|
| القيد وأسطره | `journal.JournalEntry` المجمّد مع `Lines`، و`Status = posted`، و`PostingDate`/`PostedAt` المختومان | مصدر الحقيقة المحاسبي؛ أي كتابة جزئية تترك قيداً بلا أثر قابل لإعادة البناء |
| حركة GL / الأثر القابل لإعادة البناء | تحديث الأرصدة أو ما يعادله في Adapter بحيث يتطابق مع القيد المرحّل | منع انحراف بين القيد ورصيد الحساب |
| سجل idempotency | `Key`, `Scope`, `PayloadHash`, `Status`, `EntryID`, `Response` | منع الأثر الثاني وإتاحة الاستعلام بعد فقدان الاستجابة |
| روابط العكس | قيد العكس، `ReversalOfID`، حالة الأصل `reversed`، و`ReversedByID` | منع رابط بلا أصل أو أصل معكوس بلا قيد عكسي |
| أثر التدقيق المطلوب | سجل `AuditRecord` واحد على الأقل بالشركة والفاعل والسبب والـ correlation | لا يجوز بقاء حركة مالية بلا دليل تدقيقي مطلوب |

> لا تُكتب عناصر الوحدة خارج المعاملة. لا يوجد نمط «اكتب القيد ثم ألحق التدقيق لاحقاً»، ولا استدعاء `AppendAudit` مع تجاهل خطئه.

## 4. ترتيب الالتزام داخل Adapter

الترتيب أدناه إلزامي دلالياً؛ لا يفرض لغة SQL أو اسم جدول:

1. **التحقق من العقد:** رفض `PostingCommit` الذي يفتقد `Key` أو `Scope` أو `PayloadHash` عندما يكون `Idempotency` موجوداً.
2. **حجز المفتاح داخل المعاملة:** `Claim` يستخدم النطاق الكامل. السجل المكتمل بالبصمة نفسها يُعاد كنتيجة محفوظة؛ البصمة المختلفة تعطي `ErrIdempotencyPayloadConflict`؛ السجل قيد التنفيذ يعطي `ErrIdempotencyInProgress`.
3. **تثبيت القيد:** حفظ النسخة المستلمة كما هي، بما فيها تواريخ النواة. لا يستبدل Adapter `PostingDate` أو `PostedAt` بوقت الحفظ.
4. **تثبيت العكس إن وُجد:** قفل الأصل، رفض الأصل غير المرحّل أو المعكوس، كتابة العكس، وتحديث حالة الأصل ورابطه في نفس التشغيل.
5. **تثبيت الأثر المالي:** تحديث الرصيد/الحركة بحيث يصبح مرئياً فقط عند نجاح الالتزام.
6. **تثبيت التدقيق:** إلحاق السجل المطلوب داخل نفس المعاملة؛ أي خطأ يُعاد ويؤدي إلى Rollback.
7. **إكمال idempotency:** تحديث الحالة إلى `completed` مع `EntryID` والاستجابة المحفوظة قبل Commit، لا بعده.
8. **Commit:** لا تصبح أي عنصر مرئياً قبل هذه النقطة. بعدها يمثل السجل المكتمل الحقيقة حتى لو ضاعت الاستجابة.

نقاط الحقن المتاحة للاختبارات: `FaultBeforeIdempotencyClaim`، `FaultBeforeAudit`، `FaultBeforeCommit`، `FaultAfterCommit`. الوصف الكامل في [تقرير حقن الأعطال](../reports/fault_injection_report.md).

## 5. الضمانات

| الضمان | المعنى القابل للرصد |
|---|---|
| الذرية | فشل ما قبل Commit يترك صفر قيد، صفر رصيد، صفر تدقيق، وصفر سجل idempotency دائم |
| عدم التكرار | إعادة الطلب بالمفتاح والبصمة نفسيهما تُرجع نفس `EntryID` ولا تضيف حركة |
| التعارض الصريح | المفتاح نفسه ببصمة مختلفة يُرفض بـ `storage.ErrIdempotencyPayloadConflict` دون كتابة |
| فائز واحد | الطلبات المتزامنة بالمفتاح نفسه تُرجع نفس القيد وتُنتج أثراً مالياً واحداً |
| الاستعادة بعد المجهول | خطأ بعد Commit لا يلغي الالتزام؛ البحث بالمفتاح يُرجع السجل المكتمل، وإعادة الطلب تُعيد النتيجة |
| سلامة التدقيق | أي فشل في إلحاق التدقيق يُلغي الالتزام؛ لا توجد أخطاء متجاهلة |
| طوابع النواة | القيم المختوم قبل التفويض هي نفسها المحفوظة والمُعادة |

## 6. القيود والفروض المطلوبة من Adapter

- تفرد على `(company_id, scope)` وتفرد على `(company_id, operation, idempotency_key)`؛ المفتاح المجرد وحده ليس كافياً.
- تفرد رابط العكس بحيث لا يقبل الأصل أكثر من قيد عكسي واحد.
- قفل الأصل عند العكس (`FOR UPDATE` في PostgreSQL، أو ما يعادله في Adapter آخر) لمنع فائزين متزامنين.
- `IdempotencyLookup` اختياري للمحولات القديمة، لكنه مطلوب لاختبارات العقد هذه وللاستعلام الآمن بعد unknown outcome.
- الأخطاء تُترجم إلى sentinels محايدة في `pkg/spi/storage`؛ لا تُكشف رموز SQL أو حالات السائق للمستهلك.

في PostgreSQL تُنفَّذ القيود بالهجرة `202611220001_phase7_idempotency_scope.sql`، التي تعيد ملء `scope` للصفوف القديمة ثم تنشئ المفتاح الأساسي والفهرس الفريد الجديدين. في الذاكرة تُنفَّذ التفرد وال回滚 بقفل الوحدة ونسخة لقطة قبل التعديل. هذا الاختلاف التنفيذي مسموح به؛ النتيجة Contract واحدة.

## 7. تصنيف الأخطاء

| الحالة | خطأ Adapter | قابل لإعادة المحاولة؟ | السلوك المطلوب |
|---|---|---|---|
| بصمة مختلفة لنفس النطاق | `ErrIdempotencyPayloadConflict` | لا | رفض صريح، لا كتابة جديدة |
| مفتاح ما زال قيد التنفيذ | `ErrIdempotencyInProgress` | نعم، بسياسة مضيف محدودة | إعادة المحاولة بعد فحص آمن |
| مخزن المفاتيح غير متاح | `ErrIdempotencyUnavailable` | نعم | الفشل مغلقاً؛ لا ترحيل بدون مفتاح |
| تعارض تحديث متزامن | `ErrConcurrentModification` | نعم | إعادة تشغيل وحدة العمل كاملة |
| أصل معكوس مسبقاً | `ErrEntryAlreadyReversed` | لا | فشل نهائي؛ لا يقيد عكسي جديد |
| خرق الذرية | `ErrAtomicCommitFailed` | لا حتى يُصلح المحول | خطأ داخلي؛ لا محاولة ضمنية لتكرار الأثر |
| انتهاء مهلة/فقدان اتصال بعد Commit | خطأ نقل أو `RetryableError` | نعم | استعلام آمن بالمفتاح ثم إعادة النتيجة |

التصنيف النووي موجود في `posting.IsRetryable`، وتصنيف معاملات التخزين في `storage.IsRetryable`. لا يُعدّ تعارض الحمولة أو العكس المكرر أو خرق الذرية قابلاً لإعادة المحاولة لأن إعادة المحاولة لا تغيّر نتيجتها.
